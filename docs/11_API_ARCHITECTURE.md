# 11 — API Architecture

Covers brief §49. Base URL `http://127.0.0.1:8600/api/v1`. JSON unless noted. OpenAPI generated by FastAPI at `/api/v1/openapi.json` (disabled for non-admin in production builds).

## 2. Conventions

- All IDs UUIDv7 strings. Timestamps ISO-8601 UTC.
- Every analysis call takes optional `session_id`; if absent, a new `analysis_session` is created and returned.
- Image upload: `multipart/form-data` field `image` (JPEG/PNG). Optional header `X-Client-Capture-Ms`.
- Error envelope:
```json
{"error": {"code": "CONSENT_REQUIRED", "message": "Recognition consent is required.", "details": {"purpose": "RECOGNITION"}, "request_id": "01J…"}}
```
- Pipeline "stop" conditions (NO_FACE, MULTIPLE_FACES, POOR quality) are **not** HTTP errors: return `200` with the state in the body — they are valid results.

| HTTP | Codes |
|---|---|
| 400 | VALIDATION_ERROR, UNSUPPORTED_MEDIA, IMAGE_TOO_LARGE, IMAGE_DECODE_FAILED |
| 401 | UNAUTHENTICATED |
| 403 | FORBIDDEN, CONSENT_REQUIRED, FEATURE_DISABLED, CSRF_FAILED |
| 404 | NOT_FOUND (also for other users' resources — no existence leak) |
| 409 | ENROLLMENT_EXISTS (when `replace=false`), ENROLLMENT_INCONSISTENT |
| 423 | VERIFICATION_LOCKED |
| 429 | RATE_LIMITED |
| 503 | MODEL_UNAVAILABLE, KEYSTORE_UNAVAILABLE |

## 4. Contracts (key endpoints)

### POST /bmi/calculate
Request:
```json
{"session_id": null,
 "height": {"value": 170, "unit": "cm"},
 "weight": {"value": 65, "unit": "kg"},
 "age_years": 34, "sex": "unspecified"}
```
`height.unit ∈ {cm, m, ft_in}`; for `ft_in`: `{"feet": 5, "inches": 7, "unit": "ft_in"}`. `weight.unit ∈ {kg, lb}`.
Response 200: `{ "session_id": "…", "record_id": "…", "result": <BmiResult from 04 §8> }`. On invalid input: 200 with `result.status = "INVALID_INPUT"` and `result.errors: [{field, code, message}]` (no record persisted).

### POST /face/detect
Response:
```json
{"session_id": "…", "observation_id": "…",
 "face_state": "ONE_FACE", "face_count": 1,
 "faces": [{"face_index": 0, "bbox": {"x":412,"y":188,"w":236,"h":301}, "detection_confidence": 0.94}],
 "quality_global": {"grade": "GOOD", "checks": [...]},
 "message": null,
 "models": {"detector": "face_detector.yunet@2023mar"},
 "latency_ms": {"decode": 6, "quality_global": 3, "detection": 14}}
```

### POST /face/expression
Response:
```json
{"session_id": "…", "observation_id": "…", "result_id": "…",
 "face": {"face_state": "ONE_FACE", "face_count": 1, "faces": [...]},
 "quality": {"grade": "GOOD", "action": "PROCEED", "checks": [...]},
 "pose": {"yaw": 4.1, "pitch": -2.3, "roll": 1.0},
 "landmarks": {"detected": true, "visibility": 0.98, "scheme": "mediapipe_478"},
 "expression": <ExpressionResult from 05 §6.4>,
 "models": {"detector": "…", "landmarks": "…", "expression": "…"},
 "config_version": "1-3fa9c21b0d4e",
 "latency_ms": {...}}
```
Landmark coordinates are **not** returned by default (`?include_landmarks=true` allowed for the overlay preview only; never persisted).

### POST /face/enroll
multipart: `image` (1–5 files, repeated field), `replace` (bool, default false).
Response 201:
```json
{"enrollment_id": "…", "status": "ACTIVE", "template_count": 3,
 "frames": [{"index":0,"accepted":true,"quality":"GOOD"}, {"index":1,"accepted":true,"quality":"GOOD"}, {"index":2,"accepted":false,"reason":"BLUR"}],
 "model_version": "embedding.sface@2021dec",
 "liveness": "NOT_PERFORMED",
 "notice": "Liveness detection is not implemented in this version."}
```

### POST /face/verify

```json
 "demo_uncalibrated": true,
 "liveness": "NOT_PERFORMED",
 "quality": "GOOD",
 "message": "Verified — matches your enrolled identity",
 "model_version": "embedding.sface@2021dec",
 "config_version": "…",
 "latency_ms": {...}}
```

### POST /consent
```json
{"purpose": "RECOGNITION", "decision": "GRANT", "policy_version": "privacy-1.0", "notice_sha256": "…"}
```
`decision ∈ {GRANT, DECLINE, REVOKE}`. Response: current consent row + `deletions` summary when REVOKE.

### GET /analysis/{id}  (dashboard DTO)

## 5. Production notes

- Each endpoint enforces authorization + validation in all builds (not only production).
- V2/V3: TLS (mkcert for LAN kiosk; managed certs for org deployment), OAuth2/OIDC for org identity, API versioning `/api/v2` alongside v1 for one release.
